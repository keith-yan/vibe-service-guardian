# Vibe Service Guardian 0.8.2 上线准备度审查

审查日期：2026-08-14
审查对象：本地工作区源码与本轮生成的未签名交付物
发布动作：未执行 Git 初始化、提交、推送、Release 或 OpenAI 活动申请

## 结论

**有条件通过“Windows 本机单用户公开 Alpha 候选”；不通过“Windows/macOS/Linux 全平台生产就绪”声明。**

理由不是功能数量不足，而是证据层级不同：Windows 源码、自动化与未签名便携链可在当前主机复核；macOS/Linux 只有源码、构建包与归档契约，没有真实 Mach-O/ELF 和目标驱动/桌面环境证据。真实模型矩阵、真实停止动作、跨用户权限、签名/公证和多平台供应链哈希也没有完成。

## 第一性原理判定

一个可上线的本机控制工具至少要同时满足：

1. **不会控制错对象**：PID 与创建时间、进程树、保护名单和确认短语在动作前重新验证。
2. **部分失败不说谎**：已发出的信号、仍存活进程、关闭端口和自动重启分别记录。
3. **不可信输入有硬边界**：网络响应、HTTP 请求、模型元数据、日志、SQLite 详情和快照哈希都不能无限增长。
4. **本机秘密不外泄**：运行时无遥测；日志/命令脱敏；已知秘密文件不进入快照副本；归档排除运行数据。
5. **交付物可复核**：版本、依赖、许可证、SBOM、哈希、路径安全、启动脚本和目标系统执行证据必须一致。

0.8.2 对 1–4 已形成代码和自动化证据；第 5 项在 Windows 达到 Alpha 候选水平，在 macOS/Linux 尚不完整。

## 仍未满足的上线条件

### 发布前阻断项

1. 在真实 macOS arm64、macOS x86_64、Ubuntu x86_64；如承诺 aarch64，再增加 Ubuntu aarch64，分别执行原生构建和验收脚本。
2. 在目标平台至少覆盖一组 NVIDIA、一组 AMD、Apple Silicon，并明确“厂商通用识别”不等于每张显卡的温度、风扇、功耗接口都可用。
3. 使用无真实业务数据的测试服务完成 `STOP`/端口释放/自动重启和固定矩阵端到端验收；不能拿合成单元测试替代用户可见闭环。
4. 为各平台 wheel 生成并维护哈希锁定，构建时启用 `--require-hashes`；在干净环境重建并比较 SBOM/归档结果。
5. 建立 Windows/macOS/Linux CI，至少门禁 unittest、Ruff、Bandit、依赖审计、公开目录审计、构建和归档验证。
6. 公开稳定版前完成 Windows 代码签名、macOS Developer ID 签名/公证；若保留未签名 Alpha，下载页必须明确风险并提供独立 SHA-256。

### 可在 Alpha 之后完成

- 建立真实 Codex/Claude/Cursor/Windsurf/VS Code/WorkBuddy/Hermes/OpenCode 版本矩阵与可复核夹具。
- 增加 Docker、WSL2、反向代理、需认证模型 API、日志轮转、休眠恢复与低磁盘空间的端到端场景。
- 用真实同硬件/同模型/同量化/同负载结果校准容量预测，并公布样本量和误差区间，而不是只展示点估计。
- 建立私密漏洞报告联系方式、支持周期、数据迁移/降级策略和崩溃恢复手册。

## 明确的非目标与剩余风险

- 同一操作系统用户下的恶意进程可读取该用户可访问的数据目录；VSG 不是主机级隔离或多租户控制面。
- 普通用户权限看不到的跨用户/内核进程、端口和传感器会保持“可见性受限”，不能据此证明不存在服务或暴露。
- 防火墙、反向代理和“是否认证”是只读证据判断，不执行外部攻击模拟，因此“未发现问题”不是渗透测试结论。
- Agent/项目归属是可解释启发式和有限元数据匹配；低置信度结果必须由用户复核。
- 未签名便携包可能触发 SmartScreen/Gatekeeper，且无法提供可信发布者身份。
