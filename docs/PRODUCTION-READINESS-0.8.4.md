# Vibe Service Guardian 0.8.4 上线准备度审查

审查日期：2026-08-14  
范围：0.8.4 P0 本地功能分支；不含提交、推送、Release、P1 托盘/快捷键或跨平台真机发布。

## 结论

**当前结论：可作为维护者本机 Alpha 继续试用，不应标记为跨平台稳定发布。**

0.8.4 P0 已把“停止后是否复活”和“容量估算是否有本机实测依据”做成有界、可取消、可持久化的闭环，并保留逐次确认、保护单调性、无凭据、无自动二次停止和无 OOM 探测边界。它提高的是本机决策可信度，不是无人值守运维能力。

阻止稳定公开发布的剩余事实没有被本轮掩盖：Windows 10/11 目标机型覆盖仍有限；macOS Apple Silicon、Intel macOS、Ubuntu x86_64/aarch64 没有本轮真机 P0 证据；未签名包仍会触发平台安全提示；真实 Ollama/llama.cpp/vLLM/MLX-LM 的 60 秒校准组合尚未形成公开兼容矩阵；浏览器可访问性、系统通知和长时间运行仍需人工验收。

## 门槛审查

| 门槛 | 状态 | 证据或限制 |
|---|---|---|
| 停止保护与显式确认 | 通过（自动化） | 标签不降低保护；停止仍要求 `STOP <PID>`；复活不会触发第二次停止 |
| 复活证据门槛 | 通过（自动化） | 先证明原 PID 身份消失，再接受端口重监听或同脱敏命令哈希进程 |
| 观察中止与重启恢复 | 通过（自动化） | 仅 5/15/30 分钟；中止/程序退出进入非成功终态 |
| 校准计划固定性 | 通过（自动化） | 已加载模型、并发 1/2、60 秒、`BENCHMARK <端口>` |
| 动态资源护栏 | 通过（自动化） | RAM/VRAM 85% 触发协作式取消；在途请求不强杀 |
| 档案硬件失效判断 | 通过（自动化） | 硬件指纹或 VRAM 变化自动标为可能失效 |
| 数据库升级与清理 | 通过（自动化） | schema 5、旧库迁移、状态/删除/分类清理覆盖 |
| 中英文控制台 | 部分通过 | JavaScript 语法与映射存在；仍需浏览器逐页人工核对动态文案 |
| Windows 便携包 | 通过（当前 Windows 11 主机） | 0.8.4 未签名 EXE 回环/安全/容量/观察初始态/优雅退出 smoke 通过；ZIP 41 个条目、SBOM、许可证、运行数据排除与 sidecar 校验通过 |
| macOS / Linux P0 真机 | 未验证 | 只能声明代码适配与 CI 路径，不能声明完整支持 |
| 签名、公证与自动更新 | 未实现 | 仍采用未签名便携路线，无远程更新通道 |

## 仍需在 P1 或发布前完成

1. 在 Windows 10/11 和主流 Apple Silicon Mac 上用真实服务完成端口归属、停止观察、系统通知、校准护栏、档案失效与数据库升级验收。
2. 为 Ubuntu 22.04+ 图形环境验证 `notify-send` 缺失/存在两种路径、桌面入口和权限受限提示。
3. 做中英文逐页浏览器检查、键盘导航、对话框焦点和 200% 缩放验收。
4. 用真实 Ollama、llama.cpp、MLX-LM 以及至少一个 OpenAI 兼容服务建立“运行时 × 模型 × 并发”的脱敏兼容矩阵。
5. 在准备公开预发布时重新运行 GitHub Actions、生成三平台原生包、校验 SHA-256/SBOM，并把每个平台没有真机证据的状态降级为 Preview。

P1 的托盘、全局快捷键、可选开机常驻、按项目安全清理推荐和跨平台分发不在本轮实现范围。缺少这些功能不构成 P0 代码缺陷，但构成“是否愿意每天打开”和“是否可公开分发”的产品缺口。
