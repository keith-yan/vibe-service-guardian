# 0.8.2 安全、可靠性与边界加固

Vibe Service Guardian 0.8.2 是 0.8.1 的加固版本，不新增自动关停、自动压测、自动安装或远程控制权限。目标是让“观察—评估—显式操作—验证—恢复”的本机闭环在异常输入、PID 复用、部分失败、超大元数据和退出竞态下保持可解释、可恢复。

## 1. 控制面与旧实例

- Web 控制面继续硬编码绑定 `127.0.0.1`，校验客户端、Host、Origin、随机控制令牌和请求体上限。
- Windows 使用独占端口；端口占用时只探测由 `runtime.json` 指向的候选旧实例，不结束未知监听者。
- 内部控制客户端只接受 `http://127.0.0.1:<显式端口>` 或 `http://localhost:<显式端口>`，拒绝凭据、查询、片段、非回环地址和控制字符；响应最多读取 1 MiB。
- 服务连接设置 10 秒超时，拒绝 `Transfer-Encoding` 请求，补充同源资源和浏览器权限隔离响应头。

这仍不是面向不可信多用户的认证服务器：能以同一操作系统用户读取 VSG 数据目录的进程，处于信任边界内。

## 2. 关停与停止后验证

- 发出信号前重新读取根进程和每个子进程的 PID、创建时间、名称与保护状态；无法确认身份时关闭动作。
- 进程树中出现 Agent、IDE、系统进程或其他受保护对象时，整次操作不开始。
- 温和终止和强制终止的局部错误分别记录；已发生部分动作时不会用异常覆盖事实。
- 返回 `completed`、`still_alive` 和 `errors`，并把限制写入停止后 PID、子 PID、端口及替代 PID 的有界观察结果。
- 自动重启只报告，不会触发第二次自动关停。

## 3. 归属规则与项目清单

- JSON 形式 `.vsg.yaml` 必须声明 `version: 1`；文本 YAML 子集继续拒绝标签、锚点、别名和变量替换。
- `protected` 为单调安全属性：清单和本地规则可以增加保护，不能把默认或既有保护降级为可停止。
- 受保护名称最多 256 个、每项最多 128 字符，拒绝换行和 NUL，避免配置放大与日志注入。

## 4. 日志监控与诊断

- 最多同时保持 32 个活动日志游标；身份绑定服务指纹、PID、创建时间和文件身份。
- 进程创建时间无法读取、PID 被复用、文件被替换或服务退出时关闭旧游标，不自动跟随新对象。
- 单轮仍最多读取 256 KiB；原始行不入库。文件访问错误只返回通用说明，不把绝对路径写入事件。
- 服务基准采用有界逐行读取，在分配前执行响应上限；HTTP 错误和异常信息在持久化前脱敏。

## 5. 模型元数据与本地存储

- GGUF 数组递归深度最多 16；Safetensors rank 最多 32，维度和乘积设硬上限；上游文本字段统一截断。
- Modelfile 的绝对 `FROM` 路径只展示文件名；`config.json` 仅保存允许的标量量化字段。
- 模型盘点写入 SQLite 前限制为 2 MiB，并按“截断字段—省略资产/重复组—省略模型详情”的确定性层级降级。
- 服务/模型基准详情保持为有效、有界 JSON，而不是任意截断字符串；过期模型基准进入同一历史清理策略。

## 6. 快照与回滚

- 输入文件先去重；每文件最多哈希 512 MiB，单次快照总哈希预算 1 GiB。
- 已知环境、凭据、私钥、证书和密钥库文件只进入清单，不复制内容；其他获准小配置仍可能包含未识别秘密。
- 任一步失败会清理未完成快照目录。
- 回滚前再次解析原目标，若其已被符号链接或目录链接重定向则拒绝；回滚前副本使用唯一名称，避免覆盖已有证据。

## 7. 工作负载矩阵状态机

- 单机最多一个活动矩阵，预览最多 128 个，单次任务历史最多 100 个。
- 线程创建失败会原子回退为可重试预览；审计写入失败不会把任务永久卡在“运行中”。
- 取消只阻止尚未发出的波次；终态先清除活动 ID，再做尽力审计，保证新任务不会被旧终态阻塞。
- 固定 1/2/4 并发、5/10/20 请求的边界不变，不自动扩展负载或故意探索 OOM。

## 8. 构建链与验证边界

- Windows、macOS、Linux 构建/安装入口固定引导 `pip 26.2.1`，随后以 `--only-binary=:all:` 安装精确版本依赖。
- 本地检查包含 Ruff、Bandit 中/高风险门槛、依赖漏洞审计、147 项 unittest、公开目录审计、Python 编译、JavaScript 语法和归档契约。
- 依赖尚未按平台 wheel 写入哈希，也未启用 `--require-hashes`；这是稳定公开发布前的供应链剩余项。
- Windows 上的自动化和便携包验证不能替代真实 macOS Mach-O、Linux ELF、NVIDIA/AMD 驱动矩阵、Docker/WSL 或真实模型服务验收。

完整证据见 [VALIDATION.md](VALIDATION.md)，上线判定见 [PRODUCTION-READINESS-0.8.2.md](PRODUCTION-READINESS-0.8.2.md)。
