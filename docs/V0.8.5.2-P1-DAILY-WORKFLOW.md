# Vibe Service Guardian 0.8.5.2 P1 日常工作流闭环

0.8.5.2 处理四类高频摩擦：用户无法确认当前打开的是哪个版本、跨项目逐条找遗留服务成本高、警告只在瞬时页面中出现、Windows 每次使用都要重新寻找入口。本版本不扩张进程控制权限。

## 1. 启动、升级和首次使用可解释

- 首页固定显示当前运行版本、PID、`127.0.0.1` 端口与运行时长。
- 首次使用检查展示回环绑定、项目根目录可达性、首个快照和可选模型运行时探测；用户明确完成后写入本机 `config.json`。
- 同一数据目录已有其他版本运行时，新程序继续复用已验证的旧实例，但会写入 `last-launch.json` 并在显式打开时显示本机版本冲突提示。记录只含请求/运行版本、PID、端口、时间和采取的动作，不含令牌、路径或环境变量。
- “安全退出”要求输入 `EXIT VSG`。退出会停止采集线程、中止观察和未完成工作负载并关闭 SQLite；不会停止任何被监控服务。

## 2. 按项目安全清理计划

- `/api/projects/cleanup-plans` 只根据当前快照和已有关停评估生成项目分组预览。
- 每组分别显示推荐清理、可复核、受保护/受管数量，以及端点和当前本机客户端影响。
- “推荐清理”仅来自当前可进入停止确认且风险为 `likely_stale`，或用户历史明确标记为 `safe_cleanup` 的服务。
- 受保护、Docker/WSL、Agent/IDE 和其他受管服务继续显示，但只能查看阻断证据和推荐路径。
- API 没有批量停止入口。用户从计划点击单项后，系统重新读取服务快照和关停评估，仍须输入 `STOP <PID>`；停止完成后仍进入 5/15/30 分钟观察。

## 3. 本机持久提醒中心

- SQLite schema version 7 在原 `timeline_events` 上增加 `acknowledged_at`，迁移前沿用一致性备份和单事务回滚。
- 提醒中心只展示 `warning` / `critical` 时间线事件；相同 `dedup_key` 在既有窗口中增加次数，不生成提醒洪水。
- 单条或全部标记已读只更新本机 SQLite。已读事件若之后再次命中并推进 `last_seen`，会重新变为未读。
- Web 返回不包含内部 `dedup_key`；提醒中心不增加网络、账号、遥测或云端同步。

## 4. Windows 可选桌面集成

- 托盘使用 Windows 原生 `Shell_NotifyIconW`，不引入新依赖。左键打开“今日关注”；右键菜单提供打开控制台、查看未读提醒和退出。
- 托盘默认关闭。可选快捷键只有 `Ctrl+Alt+G`，默认 `disabled`；不使用容易与无格式粘贴冲突的 `Ctrl+Shift+V`。
- 开机启动仅在冻结的 Windows 便携 EXE 中提供，并只操作当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `VibeServiceGuardian` 值。
- 启用和禁用分别要求 `ENABLE STARTUP`、`DISABLE STARTUP`。发现同名但目标不同的值时拒绝覆盖或删除；不安装 Windows 服务、不申请管理员权限。
- 本轮自动化与构建不会调用配置写接口，因此不会改动开发机的开机启动项、托盘偏好或全局快捷键。

## 5. 明确未做

- 不提供“一键全部停止”、定时自动清理或高置信度之外的自动动作。
- 不让历史标记绕过保护名单、PID/创建时间复核或停止确认。
- 不在 macOS/Linux 宣称托盘已实现；两平台仍可使用 Web 控制台和启动/停止脚本。
- 不读取目标进程环境变量、浏览器状态、剪贴板、模型响应正文或凭据。
- 不推送、发布 Release、配置签名/公证或启用自动更新。

## 6. 验收口径

- 项目计划必须声明 `automatic_cleanup=false` 和 `individual_confirmation_only`。
- v6 数据库必须备份并迁移到 v7，提醒去重、已读和复发重新未读须有自动化覆盖。
- 配置默认必须为托盘关闭、快捷键关闭、首次检查未完成；非法快捷键必须拒绝。
- 中英文首页必须可见实例信息和 P1 入口；项目计划、提醒、设置与退出弹窗须可打开，浏览器控制台不得有错误。
- Windows 便携包必须在全新临时数据目录完成回环绑定、控制令牌、归档与优雅退出验证；受限 macOS x86_64 VMware 预览证据不得被升级为实体 Intel Mac、Apple Silicon 或 Linux 完整平台声明。
