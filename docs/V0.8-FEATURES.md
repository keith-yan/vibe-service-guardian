# 0.8 事件、归属与模型资产边界

Vibe Service Guardian 0.8.0 把静态端口清单扩展为本地可追溯闭环：服务发现 → 归属纠正 → 生命周期/异常关联 → 网络暴露复核 → 模型资产盘点 → 容量与引擎决策。所有功能默认使用普通用户权限，控制台仍只绑定 `127.0.0.1`。

## 1. 项目归属优先级

扫描后的归属按以下顺序补强：

1. 进程工作目录、命令路径、父进程链和 Agent 本地元数据形成初始证据；
2. 项目目录中的 `.vsg.yaml` 可声明项目名与服务特征；
3. 控制台本地归属规则按优先级从高到低匹配，第一条命中规则生效；
4. 对具体服务的人工纠正会创建按服务指纹匹配的高优先级本地规则；
5. 具体服务指纹的“预期服务”标记保持最高针对性。

规则可匹配 `fingerprint`、`port`、`runtime`、`exe_contains`、`command_contains`、`cwd_prefix`；可覆盖项目名/路径、服务名、Agent、预期状态、保护状态和备注。覆盖的项目路径必须位于设置中的项目根目录。删除规则需要精确输入 `DELETE RULE <编号>`。

项目可选清单示例：

```yaml
version: 1
project_name: My Local Project
services:
  - name: API
    port: 8000
    runtime: Python
    command_contains: serve.py
    expected: true
    protected: false
    agent: OpenCode
```

清单必须是项目根目录下不超过 64 KiB 的普通 UTF-8 文件。首版只支持上例中的简单标量/列表，不支持 YAML 标签、锚点、别名或变量替换，也不执行清单内容。无效清单只作为采集限制披露，不会中断整轮扫描。

## 2. 生命周期、事件与遗留复核

时间线记录服务出现、退出、疑似重启、监听暴露范围改变、归属改变、模型服务远端连接开闭以及 CPU/RAM/GPU/磁盘阈值事件；日志监控产生的脱敏异常事件和每 15 秒资源样本可在事件视图中按时间窗关联。普通短生命周期开发服务不会仅因退出被标成严重事故；模型服务异常退出、暴露范围扩大和高严重度日志会提高事件健康等级。

这仍是“复核证据”，不是自动关停依据。停止普通宿主机服务仍需 `STOP <PID>`，并重新校验 PID、启动时间和受保护进程树。Agent、IDE、Windows 服务、Docker、WSL 与受保护服务保持只读。

## 3. 网络拓扑与历史隐私

拓扑节点包括本机、服务、监听端点和当前远端连接，边标识监听或连接关系；Docker、WSL、反向代理、回环、指定网卡与所有网卡监听单独分组。当前快照可显示远端 IP、端口和公网/私网作用域，用于复核模型服务是否意外联网。

远端 IP 不写入历史。生命周期数据库只保存端点摘要、端口、协议与作用域；摘要不可用于还原地址。VSG 不抓包、不读取 DNS/URL/正文、不扫描局域网，也不会根据存在 `0.0.0.0` 监听就声称端口已从公网可达。

## 4. 模型资产盘点

盘点必须同时满足：

- 用户选择已存在的绝对目录；
- 目录不是文件系统根、用户主目录、符号链接或 Windows 目录联接；
- 用户精确输入 `SCAN MODELS`。

单次最多检查 5000 个文件、向下 6 层、运行 120 秒；遇到上限会保留已取得结果并标记截断。扫描不跟随符号链接/目录联接，配置头最多读取 2 MiB，GGUF/Safetensors 元数据最多读取 16 MiB。识别范围包括 `.gguf`、`.safetensors`、`.bin`、`.pt`、`.pth`、`.ckpt`、`.onnx`、Ollama manifest、`Modelfile` 和常见 `config.json`。

盘点返回相对路径、格式、量化、架构、上下文、Dense/MoE 线索、专家数、分片组合、总权重体积与候选重复组。快速指纹只读取文件首尾有界片段，用于重复候选提示，不是完整性校验。数据库只保存所选根目录名称、根目录摘要和相对路径；绝对扫描根目录不入库。VSG 不下载、移动、删除、重命名或修改模型文件。

“当前可装载提示”只回答权重体积加保守工作区是否落入当前可用 GPU/统一内存或系统内存预算。它不包含完整 KV cache、并发、上下文、视觉编码器、吞吐和 TTFT，因此必须继续进入模型容量规划，并用同模型、同量化、同上下文、同并发的本机基准校准。

## 5. 数据清除与审计

设置中的历史清除只作用于用户勾选的本地数据库类别：服务观察、操作审计、模型基准、服务基准、脱敏日志事件、生命周期时间线、遥测样本和模型盘点历史。执行前必须精确输入 `CLEAR HISTORY`。清除动作本身会留下新的本地审计记录；归属规则、日志游标、设置、快照副本以及项目/模型/日志原文件不会被删除。

若需要完全清除 VSG 数据，应先停止程序，再由用户自行删除整个 `data/` 目录。该操作不可撤销。

## 6. 后续版本衔接

0.8.0 不做自动并发压测、自动上下文扩张、故意 OOM、自动引擎安装、驱动修改或服务编排。0.8.1 已在显式确认与资源护栏下增加**固定、可完整预览、可协作式中止**的三步工作负载矩阵，但仍不自动扩张负载、不故意制造 OOM。服务关系、关停验证、矩阵统计和容量反向校准的完整边界见 [V0.8.1-FEATURES.md](V0.8.1-FEATURES.md)。
