# 0.8.1 服务关系、关停验证与负载校准边界

Vibe Service Guardian 0.8.1 在 0.8.0 的归属、事件、模型资产和体检基础上，补全“先判断影响—再显式操作—随后验证—用实测修正预测”的本地闭环。所有新动作仍由回环控制台发起，不读取密钥，不自动停止受管服务，不自动扩大负载。

## 1. 服务关系数据模型

当前内存快照包含以下节点：项目、Agent/会话、服务、进程、监听端点和无法归属到已知服务的本机客户端进程。边类型包括项目拥有服务、Agent 关联启动、进程提供服务、服务监听端点和客户端依赖服务。

依赖边只来自操作系统当前可见的 `ESTABLISHED` TCP 连接。目标地址必须是回环地址、监听器明确绑定的同一地址，或通配监听下的本机网卡地址；公网主机即使使用相同端口也不会被认作本机依赖。连接读取受权限与瞬时状态影响，因此“未检测到依赖”不等于证明没有外部客户端、短连接或尚未建立的请求。远端地址不进入关系图历史。

Docker、WSL、Windows 服务、Agent/IDE 等可能使用不同 PID 命名空间或独立生命周期管理器。它们可以进入关系图和影响评估，但 0.8.1 不把这些对象转换为宿主机可停止目标。

## 2. 关停评估与操作边界

每个服务得到 `allowed`、`review` 或 `blocked` 决策：

- `blocked`：非普通宿主机来源、受保护、或未进入开发/模型运行时安全停止白名单；控制台只展示证据。
- `review`：存在当前本机客户端、自动重启策略、生命周期管理器或活动 Agent 关联；用户必须先复核影响，再按原规则输入 `STOP <PID>`。
- `allowed`：当前证据未发现上述阻断/复核因素，但仍不代表业务层没有使用者。

面板显示本机客户端与端点数量、监听地址、生命周期/自动重启线索、项目/Agent 归属和人工恢复步骤。恢复命令只使用已脱敏快照，VSG 不自动重放命令、启动服务或恢复会话。

## 3. 停止后验证

原停止链仍在执行前重新校验 PID、创建时间、来源、保护名单和整个子进程树。执行后，验证器在有限观察窗口中检查：

- 原 PID 是否仍以同一创建时间存在；
- 已请求停止的子进程是否仍存活；
- 原 TCP/UDP 端口是否关闭；
- 是否出现不同 PID 重新监听原端口，或 PID 被替换。

结果分为 `stopped`、`relaunched`、`stop_incomplete` 和 `verification_partial`。验证器只观察，不会对替代 PID 执行第二次停止；超过观察窗口后才发生的自动重启只能由后续生命周期扫描记录。验证数值和结果保存在本机 `stop_verifications`，可通过 `CLEAR HISTORY` 单独清除。

## 4. 固定工作负载矩阵

只有已识别、健康就绪、无需 VSG 提供凭据、且属于文本补全接口的回环模型服务才能生成计划。计划固定为：

| 步骤 | 并发 | 请求上下文上限 | 输出上限 | 样本数 |
|---|---:|---:|---:|---:|
| 单请求基线 | 1 | 512 | 32 | 5 |
| 双并发交互 | 2 | 1024 | 32 | 10 |
| 四并发持续 | 4 | 2048 | 64 | 20 |

实际上下文不会超过运行时报告上限。预览锁定服务指纹、PID、创建时间、端口和已加载模型，5 分钟失效；开始前输入一次 `BENCHMARK PLAN <端口>`。单机只允许一个活动矩阵。

开始时及每一步之前重新检查 RAM（85%）、VRAM（95%）、GPU 温度（88°C）、可见系统温度（90°C）和设置中的低磁盘余量阈值。出现身份变化、护栏阻断、OOM 证据或零成功请求时停止剩余步骤。计划不会自动增加并发、上下文或输出，也不会以制造 OOM 为目标。

中止是协作式的：尚未发出的请求波次不再启动，已经发出的回环请求允许正常返回。VSG 不通过杀死模型服务来中断请求。

## 5. 指标与统计解释

每步记录成功/失败/完成请求数、每请求生成 TPS、聚合生成 TPS、提示 TPS、TTFT P50/P95、端到端 P50/P95、近似 token 间隔和运行期资源采样峰值。P95 只有至少 20 个成功样本才标记为样本充分；较少样本仍显示数值但明确标记统计不足。

资源峰值来自控制台快照的约 350 ms 采样，不是驱动级连续追踪，可能遗漏更短尖峰。聚合 TPS 使用该步骤全部成功 completion token 与墙钟时间计算；服务端未报告 token 数时保持未知。

## 6. 容量反向校准与误差

用户可以不映射目录模型，此时矩阵只形成运行时性能历史。若选择离线目录模型与量化版本，VSG 会先保存未使用该次样本的公式预测，再计算：

`带符号误差 = (实测 - 预测) / 预测 × 100%`

`绝对误差 = |实测 - 预测| / 预测 × 100%`

只有硬件指纹、目录模型、量化、并发、请求上下文和输出长度全部相同时，服务矩阵才覆盖对应候选的同负载预测。单请求服务样本或 `llama-bench` 可以校准基础生成速度，但并发吞吐仍按工程系数外推，界面必须标为“单请求基线校准”。不同硬件或不同负载不会混用。

校准提高的是当前设备/后端/模型组合的经验拟合度，不等于生产 SLA。提示模板、采样参数、驱动、热状态、KV 实现、请求调度和模型版本变化都可能使旧样本失效。

## 7. 隐私与非目标

- 合成提示不包含项目代码、聊天或用户数据；生成正文不持久化。
- 矩阵历史保存服务/硬件指纹、目录模型 ID、量化、负载和数值结果；不保存模型绝对路径或 API Key。
- 不支持带认证服务的主动基准；VSG 不读取或代填密钥。
- 不做自动压力上探、自动最大上下文探测、故意 OOM、自动扩缩容、服务编排、模型下载、引擎安装或驱动修改。
- Windows 当前主机可验证 Windows 源码和便携 EXE；macOS 与 Linux 的新增功能仍需各目标系统原生构建和真机验收，不能用 Windows 测试替代。
