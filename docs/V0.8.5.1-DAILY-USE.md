# Vibe Service Guardian 0.8.5.1 日常使用收敛

本轮只解决四个高频问题：打开后先看什么、重复启动会发生什么、受保护服务下一步怎么做、当前本地模型到底加载了什么并还剩多少并发余量。它不扩大 VSG 的控制权限。

## 1. 默认“今日关注”

- 服务监控默认显示“今日关注”，优先纳入项目/Agent 归属、模型运行时、可停止候选、Docker/WSL，以及疑似遗留、所有网卡暴露和运行时异常。
- 未归属的 Windows 服务和仅 UDP 的普通系统噪声默认不占据首页，但完整记录始终保留在“全部”及来源过滤器中。
- 今日关注只是派生视图，不修改原始服务记录、归属证据、遗留分数、停止评估或历史数据。

## 2. 跨平台单实例守卫

- `instance.lock` 使用 Windows 文件区间锁或 POSIX `flock`，作用域是同一数据目录。不同显式 `--data-dir` 仍是隔离实例。
- 启动前先验证 `runtime.json` 对应的回环 `/healthz`、非空版本和 `instance_id`；拿到锁后再次验证，关闭并发启动竞态。
- 同一数据目录已有健康 VSG 时，新启动只复用现有控制台，不再因竞态自动占用后续端口。旧版本只要仍满足相同健康身份契约，也会被识别。
- 进程退出或崩溃后操作系统自动释放锁；锁文件本身可以保留，不构成永久阻断。锁被占用但两秒内没有健康实例证据时失败关闭，返回退出码 5 并记录本机日志。

## 3. 受保护服务建议路径

- 服务行只在允许进入确认链路时显示“停止”；受保护或受生命周期管理器托管的对象显示“建议路径”。
- Docker/Compose、WSL、Windows 服务、Agent/IDE、systemd、launchd、PM2、Supervisor 和 VSG 自身均给出对应的人工路径；可验证参数可复制，但服务端绝不执行。
- 建议面板继续展示父进程、监听端点、当前本机客户端、自动重启和恢复步骤。没有足够证据时明确要求回到原启动入口，不猜测 unit、label 或服务名。

## 4. 首批原生模型运行时适配器

- Ollama：只读 `/api/ps` 与 `/api/version`，获取已加载模型、量化、上下文和运行时报告的 VRAM。
- llama.cpp：只读 `/health`、`/props`、`/slots`、`/metrics` 与 `/v1/models`，获取加载状态、模型、上下文、槽位及被动性能指标。
- vLLM：只读 `/health`、`/v1/models` 与 `/metrics`，获取模型、调度中/等待请求和 KV 缓存指标；启用认证后不读取 Key，模型名证据可降级为未知。
- 首页显示适配器证据质量、当前模型、量化和 VRAM。并发余量只在存在当前硬件有效、模型精确匹配的本机实测档案且运行时暴露当前请求数时计算；否则显示“待校准”。

## 5. 不变的安全边界

- 不自动停止重复/旧 VSG，不自动停止受管服务，不执行建议命令。
- 不读取 API Key、目标进程或容器环境变量、Compose 正文、模型响应正文。
- 不自动下载/加载模型，不因首页探测发起 prompt 或负载测试，不故意触发 OOM。
- 控制台仍只绑定 `127.0.0.1`，无遥测、无云端同步、无自动提权。
- Windows 本机测试不能证明 macOS/Linux 已真机通过；相关声明继续保留为预览，等待 0.8.6 P2-B。

## 6. 验收口径

- 自动化：今日关注派生逻辑、VSG 进程识别、锁互斥/释放、跨版本健康身份、三个适配器、建议路径和中英文资产均有回归测试。
- 本机：首次实例只能绑定一个回环端口；第二次启动必须复用同一 PID/端口；退出后锁可重新获取。
- 页面：首页默认今日关注，“全部”可恢复完整清单；受保护服务无可点击停止入口；三个运行时的未知证据不得伪装为已测数据。
- 本文记录源码功能边界，不是发布说明，也不是 macOS/Linux 原生验收记录。
