# Vibe Service Guardian 0.8.5 P2-A 功能与边界

0.8.5 P2-A 只解决“归属误判如何被一次纠正并在本机长期复用”这一问题。它把用户显式判断变成可解释、可审计、可回滚的确定性规则，同时把 Agent/IDE 子进程和 Docker 元数据采集收紧到既定安全边界。它不是自动学习系统，也不包含 0.8.6 P2-B 的 systemd/launchd 强证据或跨平台真机发布。

## 1. 规则范围与冲突语义

| 范围 | 匹配证据 | 适用场景 | 具体度 |
|---|---|---|---:|
| `instance` | 当前服务指纹 | 只纠正当前实例 | 400 |
| `strict` | 可执行路径+工作目录组合哈希，以及脱敏命令哈希 | 启动参数稳定、希望减少误命中 | 300 |
| `standard` | 可执行路径+工作目录组合哈希 | 同项目同运行入口的后续实例 | 200 |
| `custom` | 运行时、端口或旧式局部选择器 | 手工规则与兼容入口 | 100 |
| `legacy` | 迁移前无法精确归类的规则 | 只用于兼容 | 50 |

每种范围还可因运行时、端口等附加条件增加最多 9 点，但低范围永远不能超过高范围。同一服务命中多条规则时按以下顺序选择唯一胜出规则：

1. 具体度高者优先；
2. 具体度相同时，`updated_at` 更新者优先，即最新显式用户意图胜出；
3. 时间相同时才使用优先级和规则 ID 作为确定性决胜项。

页面保留候选规则 ID、胜出规则和 `specificity_then_latest_user_intent` 决胜原因。规则和项目清单对 `protected` 仍采用单调保护：可以增加保护，不能取消内置、平台或既有保护。

## 2. SQLite schema version 6

`attribution_rules` 新增：

- `source`、`scope`、`specificity`、`revision`；
- `hit_count`、`last_hit_at`；
- `override_count`、`last_override_at`、`needs_review`。

新增本机表：

- `attribution_rule_versions`：规则快照、动作、修订号与 canonical SHA-256，每条规则最多保留最近 5 版；
- `attribution_episodes`：按服务生命周期去重的判定分母；
- `attribution_rule_hits`：一条规则对一个 episode 只计一次有效命中；
- `attribution_corrections`：脱敏的纠正前后摘要和当时命中的规则 ID。

episode 键由来源、服务指纹、启动时间和可见托管实体 ID 组合后 SHA-256 生成，不保存完整命令或路径。近 30 天纠正率为 `被纠正的唯一 episode / 唯一 episode 总数`，不是刷新次数。相同规则在同一 episode 被反复修改只算一次“规则被覆盖”；在两个不同 episode 被覆盖后标记 `needs_review`，但不会自动调权、禁用或删除。

从 schema 5 升级前仍创建一致性备份；旧规则迁移为 `source=migration`，按已有匹配字段推断范围并生成首个版本快照。较新数据库继续拒绝降级打开。

## 3. 本机规则管理

控制台“事件与模型资产 → 用户纠正规则”支持：

- 搜索规则名、项目、Agent 和本机备注；
- 查看范围、来源、启用状态、命中数、被覆盖数、最近命中时间和建议复核状态；
- 编辑规则结果并生成新版本；
- 启用或禁用而不删除规则；
- 查看最近 5 个版本，回滚时从旧快照创建一个新修订；
- 删除规则。

控制短语：

| 操作 | 确认短语 |
|---|---|
| 编辑 | `UPDATE RULE <ID>` |
| 启用 | `ENABLE RULE <ID>` |
| 禁用 | `DISABLE RULE <ID>` |
| 回滚 | `RESTORE RULE <ID> VERSION <版本>` |
| 删除 | `DELETE RULE <ID>` |

纠正服务归属时可选择 `instance`、`standard` 或 `strict`，并填写最多 300 字本机备注。纠正只改变 VSG 的本地判定，不修改目标项目、进程、启动命令或配置。

## 4. 脱敏规则包

规则包为 JSON：

- `kind = vsg-attribution-rule-pack`；
- `schema_version = 1`；
- 最多 500 条、总大小不超过 256 KiB；
- `integrity.canonical_payload_sha256` 对除 `integrity` 外的 canonical payload 校验；
- 明确声明 `cross_machine_rebind_required = true`。

导出需要 `EXPORT RULES`。导出只保留哈希型匹配证据、运行时/端口以及项目名、服务名、Agent、生命周期和布尔结果；省略本机绝对路径、完整命令、备注、`cwd_prefix`、`command_contains`、`exe_contains` 等非便携字段，并在每条规则中列出被省略字段。

导入流程固定为：

1. 本地浏览器读取用户选择的 JSON；
2. 服务端验证大小、结构、版本和完整性；
3. 只读预览唯一候选、多候选、未匹配和本机冲突；
4. 用户为每条选中规则明确选择当前服务和 `instance / standard / strict`；
5. 输入 `IMPORT RULES <条数> <摘要前12位>`；
6. 服务端重新校验规则包、当前服务和重绑定证据后写入。

没有后台同步、云端上传、机器标识交换或透明跨机匹配。导出文件仍可能包含用户自定义的项目/服务名称，分享前必须人工复核。

## 5. Agent 子进程与 Docker 隐私收紧

- 当监听服务的可见父进程链命中 Codex、Claude Code、Cursor、Windsurf、VS Code、WorkBuddy、Hermes、OpenCode、Aider 等 Agent/IDE 签名时，服务记录为 `agent.kind=managed_child`，继承 Agent/项目证据并增加停止保护。
- Agent 管理子进程不进入普通宿主机遗留评分，页面建议回到原 Agent/IDE 会话结束任务；VSG 不直接执行该建议。
- Docker 仍只读。0.8.5 不再调用无格式限制的完整 `docker inspect`，而是用固定模板只请求容器 ID、引擎 PID、重启状态/计数/策略和 4 个 Compose 归属标签。
- 模板不请求 `.Config.Env`、完整标签集合、挂载、密钥、配置正文或 Compose 文件。采集状态公开显示 `fixed_allowlist_no_environment`。

## 6. API 摘要

| 接口 | 作用 | 边界 |
|---|---|---|
| `GET /api/attribution/rules` | 规则、版本数和 30 天 episode 统计 | 只读 |
| `GET /api/attribution/rules/versions?rule_id=` | 最近 5 个规则快照 | 只读 |
| `POST /api/attribution/rules/update` | 编辑并新建版本 | `UPDATE RULE <ID>` |
| `POST /api/attribution/rules/status` | 启用/禁用并新建版本 | `ENABLE/DISABLE RULE <ID>` |
| `POST /api/attribution/rules/restore` | 从旧快照新建修订 | `RESTORE RULE ...` |
| `POST /api/attribution/rules/export` | 生成脱敏规则包 | `EXPORT RULES` |
| `POST /api/attribution/rules/import/preview` | 完整性、候选和冲突预览 | 不写入 |
| `POST /api/attribution/rules/import` | 显式重绑定后导入 | 摘要绑定确认短语 |

所有写接口继续受回环绑定、Host/Origin、随机控制令牌、JSON 类型和请求体上限保护。

## 7. 明确不做

- 不读取目标进程或容器环境变量，不读取 Compose 文件或日志正文；
- 不使用模型、启发式学习或云端服务自动生成规则；
- 不自动改变规则权重、自动禁用、自动停止或自动二次强杀；
- 不执行 `docker stop`、`docker compose down`、`systemctl` 或 `launchctl`；
- 不做后台同步、团队云规则库或跨用户监控；
- 不把当前 Windows 测试冒充 macOS/Linux 真机证据。

0.8.6 P2-B 才处理真实 systemd/launchd 单元证据和目标平台真机验收。当前验证结果记录在 [VALIDATION.md](VALIDATION.md)，上线判断见 [PRODUCTION-READINESS-0.8.5.md](PRODUCTION-READINESS-0.8.5.md)。
