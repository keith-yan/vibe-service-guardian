# Vibe Service Guardian 0.8.4 P0 功能与边界

0.8.4 P0 解决两个具体问题：停止服务后，用户能否获得一段足够长、可中止、可追溯的复活证据；容量规划能否从纯估算升级为绑定本机硬件和真实推理实例的短时实测档案。它不是自动运维系统，也不包含 P1 的托盘、全局快捷键、开机常驻、项目批量停止或跨平台发布。

## 1. 停止后持续观察

### 用户流程

1. 用户打开普通宿主机开发/推理服务详情，先查看关停影响、客户端依赖、保护状态和恢复建议。
2. 用户选择 5、15 或 30 分钟；默认 15 分钟，浏览器只在本机 `localStorage` 记忆上次选择。
3. 用户准确输入 `STOP <PID>`。VSG 在动作前再次复核 PID、创建时间、进程树、来源和保护名单。
4. 既有短时验证完成后，后台观察任务每 10 秒复核一次。顶部状态条展示剩余时间、检查次数和端口状态，用户可随时中止观察。
5. 结束后生成“成功消失 / 已复活 / 疑似被更高层进程拉起 / 证据不足 / 已中止 / 被 VSG 退出中断”报告。

### 复活证据门槛

必须先观察到原 PID 与原创建时间对应的进程身份消失，然后至少满足以下一项：

- 原 TCP/UDP 端口重新出现，监听者是其他 PID 或操作系统无法给出 PID；
- 与原服务相同的**脱敏命令哈希**出现在另一个 PID 上。

父 PID 变化和已识别生命周期管理器只用于解释“可能由更高层拉起”，不单独构成复活证据。原 PID 未消失、端口可见性失败、VSG 中途退出或观察结束后才发生重启时，结论保持“证据不足”，不能写成停止成功。观察器绝不对替代 PID 自动执行第二次停止。

### 历史生命周期标签

用户可把当前服务标为“预期服务”或“可安全清理”，并选择让后续同类进程继承。继承身份严格等于：

```text
SHA-256("v1|" + 规范化可执行文件绝对路径 + "|" + 规范化工作目录绝对路径)
```

SQLite 规则只保存摘要，不为这类标签保存两条原始路径。缺少任一路径时不生成可继承身份。“预期服务”降低遗留误报；“可安全清理”只把风险提升到人工复核级，仍不能降低内置保护、改变停止白名单、跳过 PID/启动时间复核或省略 `STOP <PID>`。

### 受保护服务建议

Agent/IDE、Docker、WSL、Windows 服务以及 systemd、launchd、PM2、Supervisor 托管对象继续只读。详情页显示来源证据和可复制建议，例如 `docker stop`、`docker compose stop`、`systemctl status <PID>` 或“回到原 Agent 会话结束任务”。这些建议包含 `will_execute: false`，VSG 服务端没有执行建议命令的接口。

## 2. 本机校准型容量规划

### 用户流程

1. 目标必须是已识别、健康就绪、无需 VSG 读取凭据、并且运行时已报告已加载模型的本机服务。
2. 用户选择已加载模型和并发 1 或 2。首版时长固定 60 秒，不提供自动递增或更高并发。
3. 页面生成完整计划；用户准确输入 `BENCHMARK <端口>` 后才开始。
4. 运行期间展示当前进度以及 RAM、VRAM、GPU 温度和磁盘采样。用户可协作式中止。
5. 完成后生成本机实测档案，并在容量页和“项目 → 推理实例”视图复用。

### 资源与请求边界

- 固定合成提示，不读取项目代码、用户聊天正文或历史会话；校准响应只在有界内存中读取以计算 token 数、TTFT 和 TPS，正文不持久化。
- 单次最多 120 个请求预算；60 秒到期后不再发起新一波，在途请求受独立有界超时约束并可正常返回。
- RAM 或任一 GPU VRAM 达到 85%，GPU 达到 88°C、系统传感器达到 90°C，或磁盘低于用户护栏时，不再发起新请求。VSG 不强杀在途推理，也不停止模型服务。
- 60 秒校准必须获得系统内存占用；检测到独立 GPU 时还必须获得至少一个 VRAM 占用读数。关键内存证据缺失时只允许预览阻断原因，不允许开始校准。
- 不自动下载/加载模型，不改上下文、量化、后端、驱动或模型参数，不故意制造 OOM。

### 档案含义

每条档案至少绑定硬件指纹、总 VRAM、服务指纹、运行时、端口、模型名、可选目录模型/量化、并发、上下文、输出长度和实测时间，保存：

- 实测 TPS、聚合 TPS、平均/P95 TTFT、成功/失败数和资源峰值；
- 理论预测及其带符号/绝对误差（仅在用户完成目录模型映射时）；
- 实测是否通过 85% 护栏、实测可用上限和推荐安全并发；
- “60 秒短时负载不能证明长期稳定性”等限制。

界面使用三个不同概念：

- **理论容量上限**：公式估算能否容纳权重、KV 和工作区；未故意制造 OOM，因此不是实验证实的物理极限。
- **实测可用上限**：该模型、该负载在本次短时测试中通过的并发。
- **推荐安全并发**：只有测试成功且资源峰值低于护栏时才等于本次并发，否则为 0。

在下次启动或用户点击“重新读取硬件”后，硬件指纹或总 VRAM 与当前机器不一致的活动档案自动转为“可能失效”；用户可手动标记过期、恢复活动状态，或输入 `DELETE PROFILE <ID>` 删除。恢复活动不能覆盖硬件不匹配判断。

## 3. 数据、并发与故障恢复

- SQLite schema version 为 5，新增 `stop_observations` 和 `calibration_profiles`；旧库仍走迁移前备份、单事务迁移和损坏隔离流程。
- 同一服务指纹只允许一个活动观察任务，单机最多 8 个活动观察；同一时刻只允许一个主动负载任务。
- VSG 重启后，未完成或正在中止的观察任务标为 `interrupted / evidence_insufficient`，不会根据中断期间不可见的状态补写成功结论。
- 停止已经完成但观察线程未启动时，API 返回 `failed_to_start` 的部分成功结果，明确提示人工刷新复核，不会把已发生的停止伪装成完全失败。
- 可选操作系统通知只调用本机固定程序：Windows PowerShell NotifyIcon、macOS `osascript` 或 Linux `notify-send`；无 shell、无网络，失败只记录类型，不影响观察报告。

## 4. 新增本地接口

| 接口 | 作用 | 控制边界 |
|---|---|---|
| `GET /api/stop-observations` | 获取活动/近期观察 | 只读 |
| `POST /api/stop-observations/cancel` | 中止观察窗口 | 不停止任何进程 |
| `POST /api/service/attribute` | 写入项目/Agent/历史标签 | 状态变更令牌；标签不执行停止 |
| `POST /api/service/lifecycle-label/clear` | 撤销历史标签规则 | 只删除 VSG 本地规则 |
| `POST /api/benchmark-matrix/preview` | 预览矩阵或 60 秒校准 | 只读预览 |
| `POST /api/benchmark-matrix/start` | 启动已确认计划 | 需要计划专属确认短语 |
| `POST /api/calibration-profiles/status` | 标记活动/过期 | 只改本机档案状态 |
| `POST /api/calibration-profiles/delete` | 删除单条档案 | 需要 `DELETE PROFILE <ID>` |

所有状态变更仍受回环来源、Host/Origin 和随机控制令牌保护。

## 5. 明确未做

- 不自动停止复活服务，不批量清理项目，不操作 Docker/WSL/systemd/launchd/Windows 服务。
- 不读取目标进程环境变量，不抓包，不读取用户提示词、聊天回复或历史会话；仅处理本次固定合成校准的有界响应，且不保存响应正文。
- 不自动申请浏览器通知权限，不强制系统通知，不安装托盘或开机项。
- 不下载模型，不搜索云端模型目录，不同步档案，不执行长时间压力测试或 OOM 极限探测。
- 不把 GitHub Actions 运行、Windows 本机结果或代码分支模拟当作 macOS/Linux 真机验收。

## 6. 0.8.4 P0 验收清单

- 历史身份哈希稳定、精确且缺失路径时拒绝继承；标签不能取消保护。
- 原 PID 未消失时，其他端口/PID/命令线索不得标为复活。
- 观察只接受 5/15/30 分钟，可中止、可持久化、重启后不会误判成功。
- 复活通知不触发第二次停止；建议操作全部 `will_execute: false`。
- 校准只接受已加载模型、并发 1/2、固定 60 秒和 `BENCHMARK <端口>`。
- 运行中达到 85% RAM/VRAM 时向请求执行器发出协作式取消，档案不得标为安全。
- 实测档案保存预测误差，硬件变化时转为“可能失效”，删除只影响 VSG SQLite。
- 项目—推理实例视图只用当前硬件有效、实测安全且与唯一已加载模型精确匹配的档案计算并发余量；同时加载多个模型时保持证据不足。
